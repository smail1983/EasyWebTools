URL Encoding Explained: Percent Encoding, Query Parameters and Examples

Learn how URL encoding works, when to encode query parameters, and how to decode percent-encoded text safely.

What URL encoding means

URL encoding, often called percent encoding, represents characters using a percent sign followed by two hexadecimal digits for each encoded byte. It is used when a character cannot safely appear in a particular part of a URL or has a reserved meaning. A space may be represented as %20 in a URL component, while an ampersand can separate query parameters. Encoding helps preserve the intended value when data is placed into a URL.

URLs have different components

A URL can contain a scheme, host, path, query string and fragment. These components use punctuation with structural meaning. A slash separates path segments, a question mark introduces a query, an ampersand separates query parameters and a hash introduces a fragment. A character that is data inside one component may be a delimiter in another. That is why encoding a whole URL is different from encoding an individual query parameter value.

How percent encoding works

Percent encoding represents bytes, not abstract visual characters. For non-ASCII text, the text is first encoded into bytes using a character encoding such as UTF-8. Each byte that needs escaping is represented by a percent sign and two hexadecimal digits. A word containing accented letters or characters from Arabic and other writing systems can therefore produce multiple percent-encoded bytes. The receiving side must decode the bytes using the expected character encoding.

When to use encodeURIComponent

JavaScript's encodeURIComponent function is designed for encoding a component such as a query parameter value. It escapes characters that could otherwise interfere with the surrounding URL structure. For example, if a search phrase contains an ampersand, encoding it as part of the value prevents that ampersand from being interpreted as the start of another parameter. The EasyWebTools URL Encoder & Decoder uses this component-oriented behavior.

Why not encode every character in a full URL

A full URL contains separators that need to remain meaningful. If you encode the entire string as though it were one parameter, the colon and slashes in the scheme and host can be escaped too, so the result is no longer a normal navigable URL. Build the URL structure first, then encode individual values that will be inserted into a query or path component. Follow the conventions of the framework or API you are using.

Spaces, plus signs and form encoding

A space may appear as %20 in percent-encoded URL components. In form-style query encoding, a plus sign is often used to represent a space, but a literal plus sign must then be handled carefully. These conventions are related but not identical in every context. When working with form submissions or a server framework, check how that system parses query strings. Do not assume that every plus sign means a space in every URL.

Common mistakes

A frequent mistake is encoding an entire URL instead of one parameter. Another is decoding text that was not encoded, or decoding the same value twice. Double encoding can turn a percent sign into %25 and produce unexpected results. Invalid percent sequences can also cause decoding errors. Keep track of whether a value is raw text, encoded once or already decoded, and avoid applying the same transformation repeatedly.

Security and validation

URL encoding does not sanitize data or make a URL safe. It only changes how characters are represented. Applications must still validate inputs, use safe URL construction APIs and avoid inserting untrusted strings into executable contexts. When a URL is received, check the scheme and host before navigating to it. Encoding a malicious address does not remove its malicious destination.

A correct component encoding step helps preserve data without breaking the URL's structure.

Frequently asked questions

Does URL encoding encrypt a URL?

No. It changes how characters are represented and does not provide secrecy.

Should I encode a whole website URL?

Usually no. Encode the individual parameter or path component while preserving the URL's structural separators.

Why do I see %20 in a URL?

It is a percent-encoded representation of a space byte in a URL component.

Is a plus sign always a space?

No. That convention is common in form-style query encoding, but a literal plus sign can also be data.
