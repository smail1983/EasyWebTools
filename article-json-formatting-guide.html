How to Format and Validate JSON: Syntax, Examples and Common Errors

By Smail Albadraoui · Published November 25, 2026 · Updated November 25, 2026

Learn JSON syntax, how to format and validate JSON, and how to fix common errors in API responses and configuration files.

What JSON is

JSON stands for JavaScript Object Notation. It is a lightweight text format for representing structured data. JSON is widely used by web APIs, configuration files, applications and services because it is readable and supported by many programming languages. A JSON document can contain objects, arrays, strings, numbers, booleans and null values. Its syntax is intentionally smaller than a full programming language: it describes data rather than instructions or executable behavior.

Objects and arrays

A JSON object is a collection of name-value pairs enclosed in curly braces. Property names must be strings in double quotation marks, followed by a colon and a value. An array is an ordered list of values enclosed in square brackets. Objects and arrays can be nested, allowing a document to represent complex structures such as users with addresses, products with variants or API responses containing multiple records. Indentation helps reveal this hierarchy.

The basic JSON value types

JSON supports strings, numbers, objects, arrays, true, false and null. Strings use double quotation marks and special characters must be escaped where required. Numbers use a defined numeric syntax and do not include currency symbols or thousands separators. Boolean values are lowercase. JSON does not include JavaScript values such as undefined, functions, comments or date objects. Dates are usually represented as strings using an agreed format.

Why formatting helps

Minified JSON often places an entire object on one line to reduce whitespace. This can be convenient for transmission but difficult for people to inspect. Formatting adds indentation and line breaks so nested structures are easier to read. It can reveal missing braces, unexpected nesting and values that are in the wrong place. Formatting does not automatically make data semantically correct; it only makes valid JSON easier to inspect.

How to validate JSON

Validation checks whether the text follows JSON grammar and can be parsed. A parser catches missing commas, extra commas, mismatched brackets, unquoted property names, single-quoted strings and invalid values. A successful parse does not prove that the data matches an API schema or business rule. For example, a field called age may contain a valid JSON string even when an application expects a number. Syntax validation and schema validation are separate steps.

Common JSON errors

One common error is a trailing comma after the last property or array item. Another is using single quotes around a string. JSON property names must use double quotes. Comments are not part of standard JSON, even though some configuration formats add their own extensions. Missing closing braces or brackets also cause parse errors. If a value contains a quotation mark or backslash, it may need escaping. Fix one syntax issue at a time and validate again.

JSON in APIs and configuration

API responses often contain nested JSON with status fields, metadata and arrays of results. Formatting makes it easier to compare fields and spot unexpected null values. Configuration files use JSON to store settings, but the exact expected schema depends on the application. A document can be valid JSON and still fail when a program expects a required property, a particular type or an allowed value. Consult the API or software documentation when syntax is valid but the application rejects the data.

Minification and safe editing

Minification removes unnecessary whitespace but should not change the data structure. It is useful when a compact payload is needed, but it makes manual review harder. Avoid editing minified text directly when a formatted version is available. For important configuration or production data, use version control and review the difference between the original and modified files. Never assume that a formatted file is correct merely because it looks neat.

Frequently asked questions

Does valid JSON guarantee the data is correct?

No. It confirms syntax only. Your application may require additional fields, types or business rules.

Can JSON contain comments?

Standard JSON does not support comments or trailing commas.

Why must property names use double quotes?

That is part of the JSON grammar; single-quoted property names are invalid in standard JSON.

No. The formatter uses the browser's built-in JSON parser and serializer locally.
